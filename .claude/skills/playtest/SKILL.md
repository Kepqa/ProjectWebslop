# Плейтест в эмуляции телефона

Тестов в проекте нет — изменения проверяются сборкой и запуском. Этот скилл даёт запуск.

## Шаги
1. `npm run build` (должен быть зелёным).
2. Поднять превью в фоне: `npx vite preview --port 4173` (если порт занят — уже запущено, можно использовать).
3. Запустить скрипт (Playwright уже установлен в окружении, `playwright install` не нужен):
   ```
   node .claude/skills/playtest/playtest.cjs --page slicing --start "#go" --out <scratchpad>/pt --drags 30 --wait 20
   ```
   Параметры:
   - `--page` — путь страницы: `slicing`, `duel`, `survivors`, `gladiatorial`, `` (хаб).
   - `--start` — селектор кнопки старта (у slicing и duel — `#go`). Без него — только скриншот меню.
   - `--device` — имя устройства Playwright, по умолчанию `iPhone 13` (портрет). Для ландшафта — `iPhone 13 landscape`.
   - `--drags N` — сколько случайных протяжек пальцем сделать после старта; `--hold мс` — сколько держать палец (по умолчанию 120).
   - `--wait с` — сколько ещё секунд просто наблюдать после протяжек.
4. Посмотреть скриншоты (`Read` по PNG): `00-menu`, `01-start`, `02-aim` (палец зажат), `03-after-drags`, `04-end`, `hub`.
5. В отчёте пользователю: что видно на скриншотах, ошибки консоли (скрипт печатает `ERRORS: [...]`), и **явно** — что ощущение и баланс так не проверить, это проверяется только на реальном телефоне.

## Чего скилл не умеет
- Не играет осмысленно: протяжки случайные, ранняя смерть бота — не признак плохого баланса.
- Не меряет fps на телефоне: headless Chromium на сервере ≠ мобильный GPU.
